# 09 · 方案 W（Workflow / 管线派）完整设计

> F4·B 的 Workflow 方案。框架取自 **Trace2Skill 的 map-reduce + SkillOpt 的 aggregate/选择逻辑**，套上[决策记录 08](./08-关键决策记录.md) 的全部决策。与 [Agent 方案](./prompts/agent-b-master-prompt.md) 并列、质量基地相同（A7），区别在**逐轨迹深度 + 结构性 ≥2**（见 §对照）。

## 一句话框架

**逐轨迹深析(map) → 跨轨迹综合(reduce) → 程序化落盘(apply)**：
- **map** = 每条已结束 session 派一个只读 agent 啃它的 jsonl，判成败 + 产单轨迹 findings（Trace2Skill per-task 结构，但**只读导航代替 ReAct-验 gold**，因在线无 gold）；
- **reduce** = 汇 N 份 findings，按"同一教训"归并、数**不同轨迹数 = support_count**、**≥2 才采纳**、失败优先 → 产结构化 skill edits（SkillOpt aggregate 的选择逻辑）；
- **apply** = Trace2Skill 目录手术 + Hermes `skill_manage`/快照，格式不过让 LLM 自修。

W 的命 = **单轨迹深度**（每条独占一个 agent，A 给不了）+ **结构性 ≥2**（独立 findings 计数，比 A 在单上下文里"扫一眼"硬）。

## 总流程

```
① 触发(共享): 某 skill 自上次 B 后被用 >X 次、只取已结束 session、claude-mem 底盘 + auto-dream 门控 + PID 锁
② 备料(代码): 列出用到该 skill 的已结束 session → 各自 jsonl 路径 + manifest;打开工前快照(curator_backup 式)

③ MAP · 逐轨迹深析 (N 个只读 agent,并行;含只读 MCP 工具)
     每条轨迹一个 agent:啃这条 jsonl(grep 导航、屏蔽噪声、只读) + 读 skill 全文
       → 判 good/poor/unclear(折入,不单设打标器)
       → poor: 失败根因 + ≤3 失败教训   |   good: 精简赢法 + ≤3 成功教训   |   unclear: 不产
       → ★若本条轨迹显出"缺部门知识"(用户手动粘内部资料 / agent 猜部门约定被纠正)
          → 带轨迹里的具体情境**当场查 MCP**,把取回的引用+摘要+provenance 嵌进该 finding★
       → 输出单轨迹 finding(带 trajectory_id + 已查到的 knowledge_ref)

④ REDUCE · 跨轨迹综合 (1 个调用,看全部 findings——findings 紧凑,塞得下)
     按"同一教训/缺口"归并(每组列出合并了哪些 trajectory_id + 为何同一条)
       → support_count = 该组不同 trajectory_id 个数;**< 2 丢弃**
       → 失败/成功各自 group+计数(门槛同,B4);冲突时失败优先
       → 为每条 ≥2 教训产结构化 edit(失败=补缺口/成功=强化;generalizable;reuse-first;按脆弱度调自由度)
       → 部门知识**主要用 MAP 已查回的**(嵌引用+摘要+provenance);仅对"聚合后才显出是部门知识形状"的漏网做兜底查 MCP

⑤ APPLY · 程序化落盘 (代码 + 必要时 LLM 修复)
     Trace2Skill 那套:TRANSLATE(近似锚点→文件精确文本) → conflict-free 写 + create↔链接配对
       → 格式 VERIFY(frontmatter/<500行/<300行/断链) → 不过则 LLM 自修一遍再校验
     经 Hermes skill_manage 校验/原子写;落 evolution_log(edit + 来源 trajectory_id + knowledge_ref)

(无 ⑥ 效果反馈/自纠/预算——决策 E / B6)
```

## 逐阶段：借自哪个参考 · 优劣 · 我们取什么

### ③ MAP 逐轨迹深析

| | SkillOpt | Trace2Skill | **我们取** |
|---|---|---|---|
| 粒度 | minibatch（M=8 条/调用） | **per-task（1 条/调用）** | **per-task**（单轨迹深度，第一层定） |
| 形态 | 纯调用，轨迹截断后 inline，无工具 | **agentic（ReAct+bash）** | **只读导航 agent**（auto-dream 式啃 jsonl）——借 Trace2Skill 的"逐条独占 agent"，但**理由是大小/噪声、不是验证** |
| 产出 | 直接产 edit | **Memory Items（Title/Desc/Content）** | **Memory Items**（中间产物，可审计、喂 reduce） |
| 成败判定 | 靠 gold（免费） | 靠 gold（免费） | **折入本阶段**（无独立打标器，第〇层定）；unclear 丢 |
| 优劣 | 调用少、早见共性；但**单条浅、截断有损** | 单条深、产可审计中间物；但**agentic 依赖 gold（我们没有）** | 取 Trace2Skill 的深 + 中间物；把它的 agentic 从"验 gold"换成"只读导航"，绕开无 gold |

> ⚠️ 诚实：去掉 gold-验证闭环后，本阶段是"**深读 + 从可观测信号(尤其用户纠偏)具体诊断**"，是具体推断、非实证（第二层）。

### ④ REDUCE 跨轨迹综合

| | SkillOpt `aggregate` | Trace2Skill `reduce` | **我们取** |
|---|---|---|---|
| 去重/归并 | dedup + 保留独特 | dedup + 保留独特 | 两者都有，**要求列出合并的 trajectory_id**（我们加固，逼扎实、可审计） |
| 共性度量 | **显式 support_count** + "prevalent-pattern bias / 单 patch 可丢弃" | 无显式计数，靠涌现 | **SkillOpt 的 support_count + ≥2 硬门槛**（更顺手做"≥2 才采纳"） |
| 失败/成功 | 失败先合、成功后合、**failure 优先**（`merge_final`） | combined 入口，失败优先 | **一次综合**内部分别 group+计数（门槛同，B4）；冲突**失败优先**（搬 `merge_final`） |
| 行级安全 | 无（单文件） | **conflict-free 行独立 + create↔链接配对** | **留到 ⑤ apply**（这层只管"改什么"） |
| 优劣 | 选择逻辑强（count/≥2/优先级）；但单文件、无目录安全 | 目录安全强；但无显式计数 | **选择逻辑取 SkillOpt，目录安全取 Trace2Skill（在 ⑤）** |

### ⑤ APPLY 程序化落盘

| | SkillOpt | Trace2Skill | **我们取** |
|---|---|---|---|
| 编辑操作 | 单文件 4 op | **目录级 8 op**（含 create/delete_file/按 section） | **Trace2Skill 8 op**（skill 是文件夹） |
| 锚点匹配 | fuzzy（`optimizer/skill.py`） | **TRANSLATE**（近似锚点→文件精确文本） | **TRANSLATE**（治"锚点对不上"通病，两家都需要） |
| 写后校验 | 无 | **VERIFY（LLM 修复 pass）** + consolidation 清单 | **VERIFY**：格式不过 → **LLM 自修**（非 rollback，B1）；+ 目录健康清单 |
| 工具/原子性 | — | — | **Hermes `skill_manage`**（frontmatter/大小/路径校验、原子写、pinned 保护） |
| 备份 | — | — | **Hermes `curator_backup`** 开工前快照（可逆底座） |
| 优劣 | 单文件不够用 | 目录手术齐全 | **Trace2Skill 完胜（skill=文件夹）+ Hermes 的工具/快照补足落盘安全** |

### 验证 / 预算（两家都不取）

| | SkillOpt | Trace2Skill | **我们** |
|---|---|---|---|
| 验证 | held-out gate（重跑打分） | agentic 重测 gold | **都不搬**（决策 E）：无效果反馈；质量靠 ≥2 入口 + 可逆 + 持续收敛 + C 维护 |
| 预算 | edit budget L + ranking 截断 | 行数上限 + minimal patch | **弃 SkillOpt 的改动数预算**（B6，be active）；**留 Trace2Skill 的行数上限 + minimal/additive** |

## 关键 prompt 草稿

### ③ MAP · 单轨迹分析 agent（每条一个，只读）

> 取材：Trace2Skill `error_analysis_system.txt` / `success_analysis_system_llm.txt` 的产出结构 + auto-dream 的"大 jsonl 窄读"。**去掉 gold/复现/重测**；判成败折入。

```text
You analyze ONE real, ended user session in which the skill "{name}" was used, to extract
reusable lessons for improving that skill.

You are given: read-only access to this session's transcript (a large JSONL — navigate it
with grep/read, do NOT dump the whole file; skip noise like full tool dumps and focus on the
user's requests, where the skill was used, any corrections, and how it ended), the skill's
current SKILL.md, and a read-only MCP tool for the department knowledge base.

First, judge how this session went for the task the skill was meant to help with:
- POORLY: the user corrected / redid / rejected the work, showed frustration, repeated tool
  errors, or the task was abandoned.
- WELL: completed smoothly, no rework, no correction.
- If you cannot tell, output "unclear" and nothing else.

Then, from what is OBSERVABLE (you cannot re-run anything; the user's corrections are your
strongest signal of what the skill should have done):
- If POORLY: give the causal Failure Cause(s) — the systematic reason the task went wrong —
  and AT MOST 3 generalizable Failure Memory Items (Title / Description / Content). Write from
  the perspective of an agent that only had the task input and this skill — describe what it
  should learn to remember.
- If WELL: give a Lean Solution Path (the minimal winning steps, dead ends stripped) and AT
  MOST 3 generalizable Success Memory Items.

DEPARTMENT KNOWLEDGE (detect HERE — the signal lives in this trajectory and is lost later):
If this session shows the skill lacked department-specific knowledge — e.g. the user manually
pasted an internal spec/convention/doc to get the task done the department's way, or the agent
guessed a department convention and was corrected — then QUERY the MCP knowledge base NOW,
using the concrete situation in THIS trajectory. If found, attach a reference + short summary +
provenance (source+date) to the relevant item. If not found or MCP unavailable, just record
what knowledge was needed. NEVER invent department facts.

Keep items generalizable, NOT task-specific. Output JSON:
{ "trajectory_id": "...", "verdict": "poor|well|unclear",
  "items": [ {"kind":"failure|success", "title":"...", "description":"...", "content":"...",
              "knowledge_ref": "<MCP source+date if fetched, else the knowledge that was needed, else empty>"} ] }
```

### ④ REDUCE · 综合 + 产 edits（一次调用，带 MCP）

> 取材：SkillOpt `merge_failure.md`/`merge_final.md`（support_count、prevalent-pattern bias、failure 优先）+ `analyst_*` 的 edit 纪律 + 我们的 trajectory_id 审计 + 决策 C（MCP 内联）。

```text
You receive the current SKILL.md and a pool of per-session findings (each item carries its
source trajectory_id). Consolidate them into a concise set of skill edits.

1. GROUP items that express the SAME recurring gap (failures) or winning pattern (successes).
   For each group, LIST the distinct trajectory_ids it merges and one line on why they are
   the same. support_count = number of DISTINCT trajectory_ids in the group.
2. DROP any group with support_count < 2 (one-off, not a systematic pattern).
3. For each surviving group, produce the SMALLEST edit that closes it:
   - failure groups: fill the gap / add the pitfall;  success groups: reinforce the working pattern.
   - Failure edits take priority; if a failure edit and a success edit conflict on the same
     point, keep the failure version.
   - Generalizable, no hardcoding. Prefer reinforcing an existing section over a new one.
   - Match specificity to fragility (recurs a lot → exact steps/checklist; varies → principle).
   - Do NOT duplicate existing skill content; do NOT touch the <!-- SLOW_UPDATE --> region or
     the frontmatter name/description.
4. DEPARTMENT KNOWLEDGE: prefer the references the per-trajectory findings ALREADY fetched
   (their knowledge_ref) — carry them into the edit. Only if a group clearly needs department
   knowledge that no finding fetched, QUERY the MCP knowledge base now as a fallback. If found,
   embed a reference + short summary + provenance (source+date); if not, derive from the
   sessions or skip — never invent.

Output JSON: edits[], each with {op, target, content, support_count, source_type, trajectory_ids,
knowledge_ref}. Use folder-aware ops (insert_after/append_to_section/replace_in_section/add_section/
create/delete_file/...). edits may be empty if nothing has support_count ≥ 2.
```

> ⑤ apply 不是 prompt：程序化 TRANSLATE/conflict-free 写/create↔链接配对 + 格式 VERIFY（不过才调一次 LLM 修复 pass，搬 Trace2Skill `verification_system_prompt.txt`）。

## 决策对齐 / 故意没做 / 观察点

- **对齐**：A5 决策E（无效果反馈）· A6/A7（≥2 带证据逼思考、不代码核验，落在 reduce 的 trajectory_id 列举）· B1（格式不过 LLM 自修 + 快照）· B2（完整 session）· B3→**per-trajectory 只读 agent 啃 jsonl** · B4（success 不额外限制）· B6（无改动预算）· 第〇层（折入成败判定）· 第一层（逐条）· 第二层（深=深读+诊断，非验证）。
- **故意没做**：gold 验证 / held-out gate / 效果打分 / 失败指纹比对 / 复发回滚 / rejected_edits / 改动数预算 / 独立打标器。
- **观察点**（接 [08 D 段](./08-关键决策记录.md)）：成败误判（尤其沉默失败被当成功）；grouping 过/欠归并致 ≥2 失真；逐条深析无 gold 的误诊率；N 次 agent 的成本。

## W vs A 总对照

| | W（本方案） | A（[agent-b-master-prompt](./prompts/agent-b-master-prompt.md)） |
|---|---|---|
| 单轨迹深度 | **深**（每条独占一个 agent） | 浅（N 条挤一个上下文 → 一行 note） |
| ≥2 怎么来 | **结构性**（独立 findings 计数 support_count） | prompt 逼 agent 自己数 |
| 调用数 | 多（N map + 1 reduce + apply），可并行 | 少（一个 agent 回合） |
| 可审计 | **强**（findings + 结构化 edits + trajectory_id 全可 log） | 中（changelog） |
| 长/噪 jsonl | **天然不怕**（每条独占 agent 啃） | 靠蒸馏压缩 |
| 成本 | 高（N 个 agent），可用便宜模型分摊 | 低 |
| 落盘 | 程序化 apply（更可控） | agent 直接 skill_manage |

**取舍**：要**单轨迹分析质量 + 可审计 + 抗长噪 jsonl** → W；要**省、快、CC-native** → A。两者质量基地（≥2/可逆/决策E）相同。

## 第六层待定（模型/成本）

- map 的 N 个逐轨迹 agent：任务相对窄（读一条、判、产 items），但**现在还要检测缺部门知识并当场查 MCP+理解返回内容**，所以模型**不能太弱**；reduce 要归并+产 edit，用强模型。N 个 map 可能重复查同一份知识 → 可加缓存。具体分配上线调。
- 触发阈值 X、minibatch 兜底（N 极大时是否把 map 改成小批）——留默认、上线观察。
